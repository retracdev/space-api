## Browser flow using official Better Auth

1. Games start in guest mode and keep guest progress locally. Offer account sign-in only when a player selects a cloud feature. Link to the existing account site; do not add an arbitrary return URL relay.
2. After an explicit account action, the game uses the official Better Auth client configured with the accounts base URL and official `jwtClient()` plugin. Credentialed requests to **accounts.retrac.space** carry its host-only cookie. A request to **api.retrac.space** cannot carry that cookie, and `credentials: include` does not change its host scope.
3. Use Better Auth's official JWT plugin `/api/auth/token` endpoint to obtain an audience-restricted access token. Keep it in memory, never in URLs or persistent browser storage. Send it to space-api as `Authorization: Bearer <token>` with `credentials: omit`. Expiry requires asking accounts for a new token. Never send the underlying session cookie or Better Auth secret to the API.
4. Games interpret `GET /v1/session` without Authorization as `{data:{authenticated:false,player:null}}`. There are no login redirects. An explicitly supplied invalid/expired token returns 401; a network/account outage is 503, not a guest state or a successful cloud save.

Same-site HTTPS account requests can use SameSite=Lax, but browser cookie restrictions and CORS must still be handled. No broadly scoped cookie is necessary. Each approved game becomes trusted to obtain a game access token, so review origin ownership and XSS risks before enabling it. Unapproved siblings remain denied.

## Account-owned changes to review and implement

- Enable the official [JWT plugin](https://better-auth.com/docs/plugins/jwt), generate and review its JWKS table migration using the pinned Better Auth release. Keep session caching disabled. Set explicit issuer `https://accounts.retrac.space`, audience `https://api.retrac.space`, a five-minute expiry, and an asymmetric signing algorithm allowed by the verifier. Override the default payload to include **only** immutable user `sub` and `sid: session.id`, plus standard issuer, audience, issued-at and expiry claims. Do not emit email, name, provider credentials or full user objects in game tokens.
- Add exact game origins to Better Auth trustedOrigins and a narrowly scoped CORS policy for the session/token routes used by games. Credentialed CORS must reflect only approved exact origins, set `Access-Control-Allow-Credentials: true`, and `Vary: Origin`. Handle preflights and wrap all error responses. The current explicit foreign-mutation guard must stay in effect on account-management paths; review any token-route exception specifically. Keep existing CSRF/origin checks and host-only cookie attributes. Never use wildcard sibling trust or expose account-management operations unnecessarily.
- Implement the following **server-only** bridge before the generic `/api/auth/` and static-asset handlers. Reject browser Origin headers and OPTIONS on these routes. Require a random 32-byte-or-longer `X-Space-Api-Key`, stored as a Cloudflare secret in both projects. Compare it in constant time. This key is separate from `BETTER_AUTH_SECRET`; never share the latter. Bound request bodies, cap directory batches at 100, sanitize errors, rate-limit, set no-store, and emit no CORS headers. Return no cookies.

| POST path under `/api/internal/games/` | Request | Success response (no envelope) |
| --- | --- | --- |
| `session` | `{}` and `Authorization: Bearer <JWT>` | `{ "id": "stable-better-auth-user-id", "username": "current_name" }` |
| `players` | `{ "ids": ["id1", "id2"] }` OR `{ "username": "current_name" }` | Array of `{ "id", "username" }`; omit deleted IDs, use exact normalized username lookup |

For `session`, verify the JWT signature using accounts' own JWKS, explicitly pin the allowed algorithm, issuer, audience, expiry, nonempty `sub` and `sid`, and maximum five-minute lifetime. Then query the existing Better Auth `session` and `user` tables: require `session.id = sid`, `session.userId = sub`, unexpired session and an existing user. Return current username from the user table. This live check ensures sign-out, session revocation, username changes and deletion take effect immediately. Never accept an unsigned token, a browser profile, or a bare user ID as proof. A missing/invalid/revoked token returns 401; database/service failures return 503. A null username is valid identity but the game API returns 403 until onboarding is finished. A bad service key should return 403, so it is distinguished from an invalid player session.

`players` reads only id and normalized username from the account user table; it must not return email, display name, images, session information or provider data. Identity data cannot be served from client claims or permanently cached in score rows. Return 200 with an empty array for unknown/deleted users, 503 for directory failures. The private key prevents this endpoint from becoming a public account-enumeration service.

The API deliberately delegates JWT and live-session verification to accounts instead of sharing its auth database or reimplementing Better Auth. The bridge creates no sessions or credentials. A Cloudflare service binding can replace authenticated HTTPS later if both deployment models support it; no additional service is needed. Review and test these changes in a separate space-accounts PR before enabling authenticated game integrations.
